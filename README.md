# Построение поисковой системы в корпоративной сети

Семестровый проект по дисциплине «Документирование и управление версиями
программного обеспечения».

**Выполнил:** Громыхалин Матвей Юрьевич, **группа ИКМО-03-25**.

Проект автоматически собирает Word-документ из исходников собственной
статьи, опубликованной в журнале «Наукосфера», 2024, № 5 (1), с. 16–21.
DOI: [10.5281/zenodo.11235600](https://doi.org/10.5281/zenodo.11235600).
Все соавторы и сведения об исходнике приведены в [SOURCE.md](SOURCE.md).

[Проверенная версия Word](result/corporate-search.docx) ·
[Автоматические сборки](https://github.com/morning728/corporate-search-docs/actions)

Структура сборки и шаблон Word основаны на
[образце kisscm](https://github.com/true-grue/kisscm).
Текст статьи, структура разделов и скрипты этого проекта подготовлены отдельно.

## Быстрый запуск

Нужны Python 3.11 или новее, GNU Make и [Pandoc](https://pandoc.org/installing.html).
Установите зависимости Python. Основная команда сборки — `make docx`:

```console
python -m pip install -r requirements.txt
make check
make docx
```

Готовый документ: **`build/corporate-search.docx`**.
Без установленного Make те же действия выполняются командами
`python tools/build.py check` и `python tools/build.py docx`.
В PDF преобразовывать документ для этой сборки не требуется.

Оглавление — поле Word. При открытии документа разрешите обновление полей
или нажмите Ctrl+A, затем F9. В переданной версии Word оглавление уже обновлено.
Для сборки не нужен исходный PDF журнала или доступ к интернет-странице статьи.

## Как изменить статью

Отредактируйте Markdown-файл в `md/` и повторите сборку.
Для нового раздела добавьте файл и его путь в `contents`.
Источник цитируется по ключу, например `[@src05, 1]`.
Pandoc сам пронумерует ссылки и список литературы по порядку цитирования.

В `project.json` можно изменить название и данные титульного листа.
Поле `article_url` необязательно: при отсутствии ссылки достаточно оставить
пустую строку. Файлы сохраняются в UTF-8.

В `md/07-supplement.md` добавлен отдельный учебный раздел с формулами LaTeX,
рисунком и таблицей. Он явно отделён от журнального текста. Схема хранится
в `images/search-pipeline.svg` и `images/search-pipeline.png` и автоматически
пересоздаётся при сборке Word. Отдельно её можно получить командой `make figures`.
Формулы Pandoc преобразует в редактируемые уравнения Word, таблицу — в настоящую
таблицу документа. Все требования перечислены в `REQUIREMENTS.md`.

## GitHub Actions

После загрузки проекта на GitHub workflow запускается при отправке изменений,
при pull request и вручную через Actions. Он устанавливает зависимости,
проверяет исходники и сохраняет Word как артефакт **`article-docx`**.

Исходники размещены в репозитории
[morning728/corporate-search-docs](https://github.com/morning728/corporate-search-docs).
Статус каждого запуска и автоматически собранный документ доступны на вкладке
Actions. В `result/` хранится проверенная версия Word; при изменении текста
актуальный результат сборки следует брать из артефакта соответствующего запуска.

## Локальные инструменты и проверка оформления

Локальная сборка проверена с GNU Make 4.4.1, Pandoc 3.8.3,
python-docx 1.2.0 и Pillow 12.3.0.
Переносимый Pandoc можно поместить в `.tools/pandoc-3.8.3/`; папка инструментов
не включается в Git. Скрипт также ищет Pandoc в PATH или в переменной `PANDOC`.

Для обновления оглавления через установленный Microsoft Word на Windows:

```powershell
New-Item -ItemType Directory -Path qa -Force
./tools/render_word.ps1 -InputDocx build/corporate-search.docx -OutputPdf qa/check.pdf -UpdateFields
```

Экспорт PDF используется для проверки верстки. Для обычной сборки в Word
этот шаг необязателен. Перед защитой прочитайте [DEFENSE.md](DEFENSE.md).
